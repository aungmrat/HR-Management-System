Attendance & Roster — UI/UX + Logic Proposal

Three connected tables: shift (definition) → duty_roster (plan) → attendance (actual). Menu group Attendance&Roster: Shift (done), Attendance, Duty Roster.
Core idea — “Plan vs Actual”
Shift→ Duty Roster (who works when)→ Attendance (who actually worked)→ Compare → Missed shifts, late minutes, overtime

Every screen answers one question: Shift = “what shifts exist?”, Roster = “who is scheduled this week?”, Attendance = “what happened today / this month?”.

2. Duty Roster — week grid (the hero screen)

2.1 Why a grid, not a flat table

Roster is a calendar problem (staff × 7 days). A flat table makes you scan rows to see one week; a week grid shows the whole plan in one glance and makes double-booking visible instantly. Keep a flat table as a second tab for filtering/export.

2.4 Cell & status logic

  • Stored status (duty_roster.status, default Scheduled): keep writes minimal — only Scheduled and Cancelled are user-set.
  • Derived display state (computed at load, colored chip — no DB column needed): Scheduled future date · Completed past date and attendance row exists · Missed past date and no attendance · Cancelled. (Join against attendance on staff_id + date in the roster query.)
  • Overnight shift: chip shows ☾ and is drawn on the start date only; tooltip shows “22:00 → 06:00 (+1 day)”.

2.5 Validation rules (the important part)

Lateness: the CHECK list has no LATE value — so do not invent one. Compute “late minutes” (= time_in − shift.start, overnight-aware, optional 10-min grace) and show it as an info tooltip / amber text in the Hours cell (“+12m late”). That matches the reference project’s calculator without schema changes.

5. Build order (phases)

Phase 1 — Attendance (read + write core)

  • Permissions ATTENDANCE_CREATE/UPDATE (enum + seed + live DB)
  • AttendanceRepository (list by date-range with staff/shift join, findById, insert, update, softDelete, KPI counts query, exists(staff,date))
  • AttendanceDialog (auto hours, auto status suggest, roster default shift)
  • Panel: KPI chips + date/status/dept filters + table + context menu; wire attendance card

Phase 2 — Duty Roster (week grid)

  • Permissions DUTY_ROSTER_CREATE/UPDATE; DutyRosterRepository (rows in week range + derived state join)
  • Panel: JTable-based week grid (7 day-columns, staff rows) — plain Swing, no custom painting needed; quick-assign dialog + change/remove popup
  • Auto-fill week batch dialog with skip-existing + result toast
  • Second tab: flat table view

Phase 3 — “Plan vs Actual” polish

  • Monthly attendance view dialog; late-minutes tooltip; CSV export
  • Roster chips: Completed/Missed derived states; “Generate attendance (ABSENT) from past roster” utility
  • Dashboard tiles: today’s present/absent, roster coverage %
